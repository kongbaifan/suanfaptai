# 连接驱动的教学动态仿真

动态计算以项目的设备、管段和有向 `connections` 为输入。设备、房间、水管、风管的读数来自同一计算步；静态 `hydraulic_network` / `steady_network` 仍是设计评估结果，不能当作当前运行流量。

## 支持的接法与建模边界

- 冷冻水、热水：闭合供回通路、串联阀门、共享主管、并联末端及可明确分辨的并联泵 / 冷热源。每条通路经过一个泵；`quantity` 表示同位并联设备组。
- 冷却水：按实际连接关联冷机、泵与冷却塔。断流使对应水冷冷机停止制冷；部分流量不足可以限制其制冷能力。空气源热泵不借用冷却塔排热。
- 风侧：机组到房间风口的送回风通路；新风机组还需要室外取风通路。允许 FCU 与新风机组在公共送风管汇合。房间分配通过风口绑定确定，CAV 风管不会因为切换制热 / 通风模式自动变成 VAV。
- 风机盘管 `air_connection_mode="room"` 表示房间直吹，`"ducted"` 表示必须接通风管。未填写时按现有空气连接识别。模板和生成器中的风管式盘管显式填写 `ducted`，删除风管后不会悄悄改为房间直吹。
- 旁通、无法唯一辨认的替代路径、网状回路、串联多泵及数量打包但位置不明的独立阀门组，返回定位诊断。其结果不能用于压力平衡结论。
- 止回阀是被动元件，不提供手动开度控制。当前依连接方向建模，不承诺开启压差、反向泄漏或阀瓣动态。防火阀开闭用于风路教学，不是消防认证模型。

不完整项目仍可启动。缺少完整供回通路的支路零输送，其他已支持子系统继续运行。新模型不通过额定值给未连接设备补水、补风；旧项目可以直接读取，但原来依赖缺线回退的结果会改变。

历史 `complete` 样例没有冷却水泵，`air` 样例还缺少完整送回风；新模型会如实给出诊断与联锁。完整运行演示可使用 `four_floor_fcu_fresh_air`、`ducted_fresh_air`、`three_floor_twelve_room` 或系统生成器。教学实验应先补齐实际连接，不能只通过打开设备开关绕过缺线。

## 流量与温度算法

拓扑在项目适配时编译并缓存。查找通路使用有向可达性、拓扑排序和上限为 2 的路径计数，不枚举全部简单路径。

管段采用 Darcy–Weisbach 教学阻力，流量单位为 m³/h：

```text
Δp = R × Q²
R = (f × L/D + ζ) × ρ / [2 × (3600 × A)²]
```

水 / 空气密度分别为 1000 / 1.2 kg/m³；摩擦系数和局部阻力默认值来自 `rules.json`。有设备额定压降与对应额定流量时可折算阻力。风口的“推荐风量 + 名义压降”不是实测性能曲线，运行阻力使用目录 ζ 与连接风管截面积，不把推荐 500 m³/h 擅自解释为 30 Pa 的标定工况。

每个计算步实行有上限的渐进分配：

1. 泵 / 风机流量和可用扬程 / 静压按转速建立能力上界；设备型号、运行台数决定额定量。
2. 末端自带水阀限定末端流量。独立阀门使用 `R(u)=R(1)/max(u,0.02)²`，`u=0` 单独判为关闭。
3. 独立阀门通流上界按其服务的不同末端参考流量之和乘开度计算；参考来源明确为计算推导。串联阀门阻力相加，上界取交集，不重复乘最终流量。
4. 共享管段的流量为经过它的通路流量之和；完整通路满足 `Σ R_e Q_e² ≤ 可用压差`，同时满足泵、源侧及末端流量上界。
5. 每次分配至少固定一条受约束通路，因此遍历次数受通路数限制，不以残差作为无限迭代终止条件。

这是**能力与压差上界约束下的教学分配**，不是厂家泵 / 风机曲线工作点。响应明确给出 `model="bounded_teaching_network"`、`pressure_balance_solved=false`。缺少几何或静压参数时的取值来自 `rules.runtime_network`，通过 `parameter_sources` 返回；项目显式声明的风机静压优先于目录静压。

每个独立水子系统分别推进供水温度，采用现有 300 s 一阶响应；回水由实际末端水量与换热量加权混合。盘管继续使用同一 ε-NTU / 湿工况焓差模型，输入实际风、水量。水侧与冷凝侧保持 3 次固定耦合迭代。稳态调用相同会话模型，并逐独立回路检查温漂，不能用全局均温抵消两个回路的相反变化。

冷却侧按 `Q_reject = Q_cold × (1 + 1/COP)` 校核可带走的热量，使用冷却塔模型同一 20 K 温升上限；额定流量比例不能直接当作制冷能力比例。COP 用额定容量计算负荷率，限流限制实际冷量，不改写额定容量。冷凝反馈取冷却塔进水（冷机排水）的温度代理，因而随排热量 / 水量变化；设备展示的送风温度与送入房间的同一股空气状态一致。

新风机组自动控制以卫生新风量为目标，使用实际风量修正转速，送风上界保持在该目标；仅用“目标风量 / 额定风量”的转速比例无法补偿管路压降。独立阀门默认全开，不隐式绑定全项目温控器；末端自带水阀继续自动调节。

## 输入与房间绑定

`RoomInput.device_ids` 继续只绑定 FCU、AHU、新风机组。新增两个独立字段，默认均为空：

```json
{
  "id": "office",
  "area_m2": 100,
  "device_ids": ["fcu_office", "fresh_air_unit"],
  "supply_air_outlet_ids": ["office_supply"],
  "return_air_outlet_ids": ["office_return"]
}
```

多个房间可以明确共用同一对风口，表示一个教学分区。一个机组只有一个可达风口且没有显式绑定时，兼容既有末端房间绑定；多个风口不能按名称或楼层猜分配，须补充绑定。FCU 与新风机组共用房间时，风口绑定不会把房间直吹 FCU 自动改成风管式。

运行中编辑项目、模式或初始房间状态仍需先停止；控制、室外条件及目标按既有热更新规则处理。

## REST / WebSocket 契约

复用现有项目、启动、控制、重置和状态接口。`GET /realtime/state/{project_id}` 与 `system_tick` 的 `data` 新增：

| 字段 | 含义 |
| --- | --- |
| `session_id` | 当前会话身份；重建后更换 |
| `simcore_tick` | 此快照的计算步 |
| `applied_control_revision` | 此步已采用的控制版本 |
| `network.circuits` | 按介质拆分的独立子系统、驱动设备、流量与供回温度 |
| `network.pipes` / `ducts` / `devices` | 逐节点实际流量、压降、状态和参数来源 |
| `network.issues` | 缺线、无法支持或运行联锁的定位诊断 |

节点 `model_status` 为 `modeled` / `disconnected` / `unsupported`。`flow_blocked=true` 表示本步没有通流；`unsupported` 的数值不代表已完成物理求解，客户端应展示“不可计算”。空气风管通过 `network.ducts` 返回，原 `/realtime/pipes` 保持水管集合。

`GET/POST /realtime/controls` 返回 `session_id`、`control_revision`、`simcore_tick`、`applied_control_revision`。控制项的 `current` 是已接受值，`effective` 是已发布计算步的有效值；模式 / 冷却水联锁可以使有效值不同。

```json
{
  "device_instance_id": "valve_branch_f1",
  "values": {"opening_pct": 0}
}
```

末端自带水阀使用 `valve_opening_pct`。房间 `target_temp_c` 必须通过仿真配置接口设置，不是设备控制项。`control_source` 为 `auto` / `manual_override`，`kind` 为 `number` / `switch`。

控制请求先完整校验、再整体接受；不存在项目 / 设备返回 404，未知参数或非有限值返回 422，有限越界值继续钳制并对齐步长。一个设备的多个参数原子接受；多个设备的多个 POST 不承诺同一步原子采用。早于同一步的重复控制以最后接受值为准。

判断指令采用必须同时核对会话身份和版本：

```text
snapshot.session_id == acknowledgement.session_id
snapshot.applied_control_revision >= acknowledgement.control_revision
```

接受控制不推进房间时间。按项目及会话串行化计算与控制；锁不跨 WebSocket 广播或其他 `await`。独立 GET 可能读到不同计算步，应使用上述身份和 `simcore_tick` 对齐。未创建真实会话的只读初始快照返回 `session_id=null`，不为生成编号创建会话。

工作台切换项目时会使旧请求上下文失效；从 A 切到 B 再回 A 也视为新的上下文。
延迟返回的配置、控制、启停响应和旧 WebSocket 事件不能覆盖当前项目。启动操作捕获
点击时的项目 ID；配置保存完成后若已切换项目，则不再发送后续启动请求。

仿真期间 `POST /api/v1/realtime/update` 返回 409，错误码 `RUNTIME_STATE_REQUIRES_STOP`，防止外部数据覆盖仿真快照。停止后的独立设备状态上报保留；该类数据不带仿真会话 / 网络求解承诺。

## 验证与教学解释

回归覆盖独立 / 串联 / 主管阀、断回水、极小管径、独立回路、冷却水停泵、风阀分区、实际水风量、守恒、并发控制、版本确认及 REST/WS 一致性：

```powershell
pytest tests/test_network_flow.py tests/test_runtime_network.py tests/test_runtime_network_api.py
pytest
ruff check app tests
mypy app
cd web
npm run test:unit
npm run typecheck
```

温湿度判断使用长窗口均值、带宽和单步变化；不能用一个时刻判定收敛。比较冷机功率时同时比较供冷量与 COP：相同冷量下 COP 下降会增加功率；限流导致冷量下降时功率也可能下降。旧的“任何冷却恶化都必然增加功率”不是有效的验收条件。
