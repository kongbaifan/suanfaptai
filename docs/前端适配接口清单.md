# 前端适配接口清单

面向 Vue 前端（`web/`）适配的接口清单，基于 `app/main.py` 当前 52 个路由（51 HTTP + 1 WebSocket）逐个核对整理。
Unity 桥接链路已移除，Vue 工作台是唯一客户端，本清单按此前提划分收录范围。

> 生成日期：2026-09-08。接口级字段语义详见 [接口文档.md](接口文档.md)，本清单不重复展开字段表，只给适配所需的路径、模型、错误码与消费方。

## 1. 总览

| 分档 | 数量 | 说明 |
| --- | --- | --- |
| 主体：已接入 | 24（含 WS） | 前端当前实际调用，含 store action → 页面映射 |
| 主体：待接入 | 9 | 建议接入的产品缺口，分高/中/低优先级 |
| 附录：暂不接入 | 18 | 聚合冗余 / 管理调试 / 边缘，前端不写适配代码 |
| 静态入口 | 1 | `GET /` 托管 Vue 构建产物（浏览器直达，非 API 适配对象） |
| 合计 | 52 | 51 HTTP + 1 WS，与 main.py 路由数一致 |

**通用约定**：

- Base URL：开发期 Vite 代理（见 `web/vite.config.ts`），部署期同源；所有业务路径前缀 `/api/v1`
- 无鉴权；JSON 请求/响应
- 错误响应 `detail` 有三种形态（`web/src/api/client.ts` 的解析逻辑已对齐）：
  1. 字符串（404/422 常规错误）
  2. `{code, message}` 对象（409，如仿真运行中禁止编辑项目）
  3. Issue 数组（422，房间绑定/配置校验，每项含 `code/message/severity`）
- WebSocket 断线由前端自动重连（指数退避，最多 6 次，上限 15s，`web/src/stores/realtime.ts`）
- 评估计算耗时较长的接口（system/evaluate、steady-state）无异步任务机制，同步阻塞返回，前端需 loading 态

**已知文档滞后**（本次仅记录，不修改）：

- [接口文档.md](接口文档.md) 开头写 "48 个 HTTP 端点"，实际已是 51 个（新增 devices/ports 后未更新计数）

**WebSocket 事件**（`{type, data}` 信封格式）：

| 事件 | 语义 | 前端处理（已实现） |
| --- | --- | --- |
| `connected` | 连接确认 | 标记 socketState=connected，清零重连计数 |
| `system_tick` | 仿真推进一拍 | 更新状态缓存并并行拉取 rooms/pipes/controls |
| `device_state_updated` | 设备状态变化（**增量**） | 按 device_id 合并进现有快照（不可整体替换） |
| `simulation_status` | 启停状态变化 | 同步 running 态 |

消费方：`stores/realtime.ts`（activate/connect/loadState/loadHistory/loadConfig/loadControls/loadRooms/loadPipes/loadRated/saveConfig/setDeviceControls/resetControls/start/stop）→ RuntimeView 为主，HistoryView/DiagnosticsView 辅助。
